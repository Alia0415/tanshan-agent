## 1. Agent 问答：从问题到适合处境的帖子

标准模式可试问：“应届生拿到两个 Offer，一个异地高薪但加班多，一个本地薪资低一些，该怎么选？”

1. 根据当前追问选择选项，或自由补充薪资、通勤、成长目标与个人时间安排。
2. 观察后续追问是否针对刚补充的约束；最多 5 轮，也可跳过。
3. 查看推荐帖子的标题、摘要、筛选说明和原帖入口，再按需展开辅助总结。
4. 修改条件重新检索，检查旧回答是否保留、当前回答是否使用新条件。

公开体验请从页面提供的样例主题开始，不将样例帖子当作真实知乎检索结果。

## 2. 阅读助手：找到该从哪里读

1. 独立进入 `/reading`，浏览热榜、曾经上榜的问题，或搜索感兴趣的话题。
2. 对已记录上榜的问题生成阅读地图；按实际关注点回答阅读助手的问题。
3. 切换路线，观察对应文章如何变化；展开节点查看精选材料。
4. 打开一篇文章，查看基于搜索摘要生成的思维导图，再从原文入口继续阅读。

地图用于组织阅读方向，导图用于预览内容结构。两者不表示已经获取或核验文章全文。

## 3. 观点圆桌：让分歧变成可继续追问的问题

1. 独立进入 `/roundtable`，输入话题或选择页面样例。
2. 查看主持人与不同立场角色入席，观察发言、角色动作和观点气泡的同步。
3. 开启自动讨论，或直接发送一条具体追问，例如“如果每周要留十小时做自己的项目，应该向 HR 确认什么？”
4. 查看相关角色的针对回应；展开论据、完整发言和对应来源。

角色由同一模型模拟不同立场。没有有效引用的发言会标记待核实；角色数量不代表独立模型数量。

## 联调与回归检查

受控验证使用 `npm run check` 与 `npm run build`。HTTP 验证需先启动对应模式的服务：

| 命令 | 验证范围 |
| --- | --- |
| `npm run test:smoke` | 原有问答 demo 的卡片与文字消息接口 |
| `npm run test:public-demo` | 无 AI 密钥的全站公开样例；发现 AI 已启用时会停止 |
| `npm run test:zhihu` | 显式请求知乎搜索与直答，会消耗对应额度 |
| `npm run test:clarification` | 显式验证模型追问，会请求外部服务 |
| `npm run test:search` | 显式比较检索规划与筛选效果，会请求外部服务 |

手动检查条件编辑、刷新恢复、来源打开、错误回退和手机宽度下的输入。真实接口的相关性、延迟与语义引用支持度需要另行评估，不能用样例结果替代。

当前交付为 Web 应用与 Agent 核心框架；知乎站内宿主的身份验证、协议适配和发布仍需单独联调，见 [Agent 范围](AGENT_SCOPE.md)。
