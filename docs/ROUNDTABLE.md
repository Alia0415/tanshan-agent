# 观点圆桌（实验能力）

从原型的多 Agent 圆桌移植而来：针对一个知乎问题，用真实检索到的帖子组建 2–3 个立场 Agent 加主持人，逐轮陈述、交锋、插话和总结，访客可随时发言并由最相关的 Agent 回应。

## 位置

- `src/lib/roundtable/`：纯编排引擎与提示词，不依赖数据库、Next.js 或浏览器。
- `src/lib/server/roundtables.ts`：SQLite 存储（`roundtables` 表，匿名会话隔离，24 小时过期）与知乎直答接线；`roundtable-mutation.ts` 提供 `roundtable_locks` 表上的跨进程互斥。
- `src/app/api/roundtables/`：列表、创建（支持 NDJSON 进度流）、读取、推进、访客发言、邀请嘉宾、摘要与证据要点接口。
- `src/app/roundtable/`：本地调试页面。

## 接口与并发保护

- **互斥锁**：每次写操作（推进、发言、邀请嘉宾、生成摘要）先在 `roundtable_locks` 表为该圆桌登记一把带 10 分钟过期的锁，占用中的圆桌再来请求会返回 `409 ROUNDTABLE_BUSY`，且不会发起任何付费调用；模型完成后在同一事务里校验锁归属再保存，锁被抢占时返回 `409 ROUNDTABLE_CONFLICT`。锁存在数据库里，多进程部署同样有效。
- **轮次去重**：推进请求携带 `expectedTurn`（客户端持有的 `scheduler.turn`）。与库中不一致说明已被别的请求推进过，服务端直接返回当前圆桌而不调用模型，前端据此静默同步。
- **失败不重试**：模型失败或限流时释放锁、不落库、向用户展示可重试的错误；唯一的自动第二次调用是快模型返回非 JSON 时换备用模型补一次（见下）。

`GET /api/roundtables` 返回当前浏览器会话下未过期的圆桌摘要（最新 10 场），前端开局页据此提供"继续上次的圆桌"入口，刷新后可恢复到服务端保存的进度。创建接口在 `Accept: application/x-ndjson` 时按行推送检索进度与已找到的资料，最后一行给出完整圆桌。

## 调度规则

- 角色生成后，开场白来自主持人；观点陈述一次调用批量生成（各角色互不依赖）。
- 交锋一次调用生成一问一答两段；第二段回应第一段。
- 三位可选 Agent 默认不参与讨论；用户从 Agent 库拖入场景后，才调用对应 Agent 发言。重复拖入不会重复调用，生成失败可重新拖入。
- 新圆桌生成 1–3 个具体议题；模型未提供议题时以原问题为议题。每次交锋聚焦一个尚未结束的议题，同时返回进展，不增加单独的调度模型调用。
- 议题可以标记为已澄清、待补证据或保留分歧；每个议题最多两次交锋请求，仍未澄清则保留分歧。所有议题处理完后总结，24 条消息仍作为安全上限。旧存档没有议题时沿用 8 条交锋阈值。
- 总结后访客发言仍然开放，既有总结不会自动重写。
- 单个模型扮演全部角色：角色差异来自提示词和各角色分配的知识库（批量请求含多个角色的材料，尚非独立调用隔离），引用编号必须属于该角色知识库，否则被丢弃；正文和摘要中的无效数字引用同步移除，绝不自动补其他来源。无有效引用的发言在聊天区标记为尚待核实。编号有效不代表已完成语义事实核查。

## 边界与约定

- 仅在配置 `ZHIHU_ACCESS_SECRET` 时可用；创建时执行两次真实搜索并去重，帖子不足 4 条时明确拒绝，不编造材料。
- 模型输出经 zod 校验；无效的角色、发言或引用被丢弃而不是整场失败。
- 模型选择：`ZHIHU_ROUNDTABLE_MODEL`（默认跟随 `ZHIHU_ANSWER_MODEL`，再默认 `zhida-thinking-1p5`）。推荐设为 `zhida-fast-1p5`：组局约 4s、每轮 4–13s，而 thinking 约 39s / 23s。快模型偶尔会用散文而不是 JSON 作答，这一种情况会用 `ZHIHU_ROUNDTABLE_FALLBACK_MODEL`（默认 `zhida-thinking-1p5`）补一次；限流、超时和上游错误仍然不自动重试。
- 并发保护：推进、访客发言、邀请嘉宾和摘要生成都经过 `roundtable_locks` 表的跨进程互斥（`ROUNDTABLE_BUSY` 409），提交前再校验锁归属；推进请求携带 `expectedTurn`，与库中轮次不一致时直接返回当前圆桌而不调用模型。自动讨论在每次响应后 800ms 连续推进，模型耗时与舞台动画重叠。
- 刷新恢复：`GET /api/roundtables` 返回当前浏览器下未过期的圆桌摘要（最新 10 场），开局页据此提供"继续上次的圆桌"入口。
- 来源（含摘要）随圆桌载荷持久化，重启后可继续；本轮未接入应用级配额治理，属后续工作。

## 验证

- `npm test` 覆盖引擎的角色校验、批量陈述、成对交锋、嘉宾顺序、总结条件与访客发言（`tests/roundtable.test.ts`），互斥锁的占用、释放与失效（`tests/roundtable-mutation.test.ts`），以及服务端的并发拒绝、`expectedTurn` 去重、失败释放锁、列表隔离（`tests/roundtable-store.test.ts`）。
- 调试页 `http://localhost:3000/roundtable` 可手动走完整流程。

## 并发与恢复

- 所有圆桌写操作在 SQLite 中按圆桌 ID 互斥，涵盖讨论推进、访客发言、嘉宾和摘要补全；冲突返回 409，不启动第二次模型调用。
- 每次写入前校验锁令牌及有效期；10 分钟租约到期后允许新请求接管，旧请求无法覆盖新结果。异常时释放自己的锁，不删除接管者的锁。
- 推进接口要求 `expectedTurn`，过时的推进请求直接返回当前圆桌，不重复生成。前端自动播放遇到忙状态会稍后再检查。
- 摘要补全遇到忙状态可手动重试。此机制没有对用户插话、创建圆桌实现跨请求幂等，也不会自动重放失败的付费调用。
- 证据不足时展示所缺材料；本轮未新增自动检索或逐论点语义核验。
