# 按用户当前状态匹配知乎帖子

用于个性化帖子推荐，以及探山的追问、检索和排序设计。成功标准是推荐内容对用户目前处境有参考价值。主题相关或高赞本身不足以证明适用性；不能承诺找到了知乎全站最符合用户的内容。

## 理解当前状态

从原问题和历轮回答中提取与本次需求有关的信息：当前阶段（了解、准备行动、已经遇到问题）、具体处境（相关经历、基础、环境）、现实限制（预算、时间、地点、不可接受的代价）、当前诉求（想解决什么、主要纠结什么）。这些是理解维度，不是必填字段或固定提问顺序。

只把用户明确表达的信息记为已确认；未知信息保持未知。用户最新明确修正优先，保留问答对应关系以理解简短回答。不从一句话、收藏或阅读行为推断身份、收入、心理状态或长期画像；不为推荐默认读取账号数据。

粗标签不等于了解处境。“工作三年”不说明当前职业基础，“想转行”不说明目标，“预算不多”不说明可投入范围。对会改变帖子适用性的维度，继续了解具体起点、期望变化、已尝试的方法与结果、当前卡点和可投入资源。具体到能区分推荐方向即可，不要求精确数字或完整个人履历。

在内部区分“已明确”“仍粗略”“未知”“不愿提供”：已明确的信息不重复问；仍粗略的信息只有在不同解释会改变推荐时才深入；未知信息不默认补全；不愿提供的信息不再索取。只问会影响当前问题解决方向的信息；确需背景时，用相关经历、技能基础、预算范围等适用性信息，不索要姓名、联系方式、精确住址或具体单位等身份标识。

## 是否追问

每轮先判断：用户究竟卡在哪里，尚不清楚的是问题本身的哪一个分歧？这个缺口是否会改变要找的解决经验、比较依据或帖子适用性？在内部明确缺口，以及不同回答会怎样改变检索对象或帖子优先级。只有不同回答会明显改变匹配，而且改善值得用户付出回答成本时才追问。只会丰富 AI 总结、增加个人资料或让排名轻微波动的缺口，不值得打断用户；不虚构数值来衡量追问价值。

- 每轮追问最影响匹配的一个具体缺口，承接用户刚说的内容，简短说明它会影响寻找哪类经验；可给少量选项，也允许自由补充。不要把多个独立背景问题塞进一轮。
- 已明确回答或拒绝提供的信息不再问，包括换一种表述询问同一缺口。允许在粗略回答上深入到新的具体子问题，例如已知“想转行”后问目标方向；这不等于重复问是否转行。若用户修正造成影响匹配的实质矛盾，做针对性确认。
- 在结束前检查：根据已知信息，是否仍存在两种合理处境，需要明显不同、甚至相互不适用的帖子？若是、改善值得回答成本且用户愿意继续，就追问最能区分两者的缺口；不能只因已知道职业、目的或一个偏好就提前结束。若关键推荐方向已经稳定则立即检索；不为填满画像继续问，总共最多 5 轮，不设最低轮数。
- 多种合理处境可以由同一组内容及清晰的差异说明覆盖时，直接检索，不要求用户先做取舍。若新增答案已无法改善现有候选，且没有剩余检索能力或预算，也停止追问。
- 客观事实题、明确要求整体了解、直接回答或跳过时直接检索。用户表示不知道或不愿补充时按已知条件继续，并说明适用性尚不确定的部分。
- 当已有结果或轻量检索结果可用时，可依据其中不同的适用场景定位缺口；不把先检索设为每次追问的必要步骤，也不突破调用预算。

例如“要不要考研”尚不明确当前阶段时，可以问“你目前是在校准备考研，还是已经工作后考虑再读研？”；若用户已说“工作三年，想通过考研转行”，不再问是否工作，只有转向领域等缺口会明显改变适用帖子时才继续问。

### 沿问题深入，再按需补背景

追问的目标是让问题更可解决。用户已经给出具体困难、矛盾或失败经历时，优先沿这条线索追下去，不先退回身份、年限、水平和预算。即使这些背景未知，也不代表必须补齐。问题过于宽泛、没有具体线索时，才从关键用途、起点或目标中选一个能打开方向的问题。

生成前在内部明确三件事，不向用户展示分析过程：

1. **承接什么**：从原问题或最新回答中找到具体线索，例如“照着教程会，自己写不会”。没有这样的线索就承认问题仍宽泛，不虚构卡点。
2. **区分什么**：至少两种合理解释或解决路径，例如“不会拆需求”和“知道步骤但写不出来”。优先问可观察的表现、发生环节、尝试后的反馈，别要求用户自己诊断原因。
3. **回答后怎么用**：不同回答分别对应什么检索主题或筛选依据。若答案只会增加个人资料、改变措辞，或无论怎么答都找同类内容，就删掉这道追问并检索。

根据线索选择一种深入方式，不按顺序问完：

- **模糊现象变具体**：问发生在哪个环节、什么情况下出现、期望与实际有什么差别。
- **已有尝试往下追**：问做完后哪部分有变化、哪部分仍卡住；已说明方法和结果时，不重问“试过什么”。
- **矛盾或选择往下追**：问哪个具体收益、代价或不确定性阻碍决定，不把用户的多个愿望强行压成单一目标。
- **观点或解释范围不明**：必要时问用户想厘清哪处争议或比较；不要把公共议题变成个人经历访谈。范围已明确的知识题直接检索。

候选背景问题与问题本身的追问同时存在时，优先选择更能区分解决方向的那个；价值相近时优先深入已有线索。准备连续问第二个背景问题前，重新检查上一轮回答是否已经出现可深入的卡点，不因为画像还有空格就继续收集。背景问题没有固定配额，深入问题也没有最低数量。

不要把“为什么”“本质是什么”当作深入的标志，不预设用户动机或故障原因。例如“你是不是不够自律？”应改为具体行为或中断环节的询问。选项应呈现当前问题下可辨认的情形，不能暗示某种解释已经成立。

### 必要时识别会改变推荐的起点

当原问题宽泛、尚无更具体的卡点，而不同经验或阶段需要明显不同的材料时，可先问相关起点。若用户已经指出“夜间拍孩子容易糊”等具体问题，先区分问题表现，不因为相机使用年限未知而退回经验分级。起点不是其他追问的前置门槛；关键条件已充分或用户要求停止时，直接检索。

用与话题有关的具体经历、已做的事情或当前进展提问，让用户容易回答。避免笼统问“你是什么水平”“你是什么身份”，不考知识，不把新手、老手当成固定人设。问题标题或帖子里出现“新手”不代表用户本人是新手；也不从专业术语、年限或器材价格推断能力。用户已明确说过的起点直接使用，不再换一种说法确认。

| 话题与未知起点 | 可优先问的一个问题 | 回答如何改变后续方向 |
|---|---|---|
| 器材选购，相关使用经历未知 | “你目前使用这类器材的经历更接近哪种？”选项需替换为当前器材的具体使用经历 | 首次使用侧重实际用途、上手条件；已有使用经验且想升级侧重现有器材的限制，不默认新手预算低或老手要升级 |
| 学习编程，已有实践未知 | “你目前用编程做过哪些事情？” | 尚未实践侧重入门路径；做过练习或项目侧重下一步目标与具体卡点；已有其他语言经验不当作完全零基础 |
| 职业转换，行动阶段未知 | “你目前转行这件事进行到哪一步了？” | 探索方向侧重相似起点的选择经历；已经学习或投递侧重能力差距、作品或求职反馈，每轮只选一个关键缺口 |
| 备考，准备进展未知 | “针对这次考试，你目前准备到哪一步了？” | 尚未开始侧重准备路径；已有复习实践侧重薄弱环节和方法调整，不重复推荐泛泛的开始准备经验 |
| 解决反复出现的问题，已有尝试未知 | “针对这个问题，你已经试过哪些办法？” | 未尝试侧重可行的第一步；试过但无效则了解结果或阻碍，避免重复无效建议 |

这些是分支示例，不是固定题库。生成时使用用户话题中的具体对象，按“单选与多选”规则设计选项；不同经历可能并存时不能强制单选。每次只了解一个关键缺口，不在同一题同时索取水平、目标、预算和时间。后续问题须承接回答：已知起点则问新的关键缺口，信息足够就停止，不凑轮数。

起点信息必须影响检索或筛选，例如区分入门实践与进阶排障、方向探索与行动复盘。不能只改变回答语气、术语难度而忽略实际适用性；若同一篇内容确实覆盖不同起点，可以保留并分别指出对应部分，不为证明个性化而强行换帖；也不能仅凭阶段标签排除能直接解决当前问题的材料。

### 背景确有必要时，补到可用即可

以下仅用于背景缺口比具体问题更影响匹配时，不代表“领域→基础→时间”的连续提问链。每轮只选择当前最关键的一项，原话已包含的直接使用。

| 已知信息 | 仍可能影响匹配的缺口 | 可用追问及用途 |
|---|---|---|
| 工作三年，想通过考研转行 | 希望进入的领域 | “你希望通过考研转向哪个领域？还没确定也可以说。”用来区分专业转换与职业探索经验 |
| 希望转向计算机 | 当前专业或编程基础 | “你目前的编程基础大概怎样？”区分零基础跨考与已有技术基础的经历 |
| 零基础，在职备考 | 可持续投入的时间 | “备考期间你每周大约能稳定投入多少时间？”区分在职有限时间与全职备考经验；不自动假设能辞职 |
| 想跳槽，主要因为太累 | 疲惫的具体来源 | “目前最让你累的是工时、工作内容，还是团队相处？”区分换公司、换岗位与沟通应对经验 |
| 已尝试与室友沟通，仍受影响 | 沟通后的反应或实际卡点 | “上次沟通后，对方是什么反应？”区分未达成约定与约定反复失效的经验，不再推荐泛泛的首次沟通帖子 |

若用户已经说“工作三年，文科背景，零编程基础，想跨考计算机，只能在职备考，每周约十小时，想看相似起点的真实经历”，可以开始检索，不再收集年龄、单位或收入来凑画像。目标尚不确定时，优先找相似起点的方向探索经历，不强迫用户先做出决定。

### 多轮示例：每次回答都应改变下一问

以下展示分支逻辑，不是逐字复用的题库。每个箭头是一轮；实际信息充分时提前检索。

| 原问题与已知信息 | 更有价值的追问 | 用户回答后如何继续 |
|---|---|---|
| “学 Python，总是看得懂教程，自己写就不会。” | “不看教程自己写时，你会卡在哪些环节？”可给需求拆分、写具体语句、报错排查等可并存情形，使用多选 | 若答“不知道怎么拆需求”，需要进一步定位时问“拿最近想写的小功能来说，你想让它完成什么？”；若已给出具体任务与卡点，直接找需求拆解的实践经验，不转问学历和每周时间 |
| “要不要考研？工作三年，想转计算机，怕读完仍找不到工作。” | “对读完仍找不到工作，你最想弄清哪方面的不确定性？” | 若答“非科班读了研会不会还是被筛”，检索跨专业硕士求职与招聘筛选经历；不按模板继续收集预算、作息，也不把担忧当成已证实的招聘规律 |
| “相机晚上拍孩子总糊，要不要换机身？” | “糊的照片更接近什么表现？”可用孩子拖影、整张抖动、焦点落在别处等情形，允许自由描述 | 若答“背景清楚，孩子手脚拖影”，已有明确线索；若拍摄参数会区分光线限制与设置问题，可问“拍糊的那张快门速度是多少？不知道也没关系。”，据此找运动模糊与低光拍摄经验，不直接认定器材不行 |
| “提醒室友晚上小点声，答应了还是照旧。” | “答应之后，有过一段时间变安静，还是一直没变化？” | 分别寻找约定难以持续或约定没有落实的处理经验；若用户补充了明确原因或限制，沿该信息调整，不重问是否沟通过 |
| “远程办公为什么有时反而降低效率？” | 若只要求解释，直接检索；只有所指效率含义影响范围且不明确时，问“你关注个人任务完成，还是团队协作的效率？” | 若答“团队协作”，找协作延迟与协调成本的材料；不问用户职业、公司规模和居家条件来补个人画像 |

一个反例：“跟教程会、自己写不会”→“什么学历？”→“学了多久？”→“每周有几小时？”连续丰富背景，却没有辨认学习障碍。即便每题都能用于筛选相似经历，也应优先找到真正卡住的环节。

### 单选与多选

先明确这道题要了解的一个信息缺口，再判断用户在题目限定的对象、时间和范围内，能否同时真实地选择两项。模式由语义决定，不由选项数量、视觉样式或“主要”等单个词决定。

- **单选 `single`**：同一范围内互斥的状态、互不重叠的数值区间，或确实需要确定的唯一首要目标。题干明确“当前”“本次”或“最优先的一项”等必要范围。选中另一项时替换原选择；再次点击已选项可以取消。
- **多选 `multiple`**：同一信息缺口下可以并存的用途、偏好、困难、限制或已有尝试。题干用“哪些”“涉及哪些方面”等表述，明确可多选；逐项添加或取消，不替换其他已选项。选择的先后顺序不代表优先级。
- **自由输入**：选项难以准确覆盖，或需要具体数字、描述时，可不提供选项。探山此时使用空 `options` 和 `single`；界面无需显示选择模式，仍允许输入文字。

| 信息缺口与题干 | 模式 | 判断依据 |
|---|---|---|
| “本次买相机的总预算在哪个区间？” | 单选 | 同一笔总预算只能落在一个区间；如低于 3000 元、3000 至不足 6000 元、6000 元及以上，边界不能重叠 |
| “你会用相机拍哪些内容？” | 多选 | 风景、人像、视频可以同时需要 |
| “如果只能先解决一个问题，你最优先希望改善什么？” | 单选 | 明确收集唯一优先项；只有该取舍会影响推荐时才这样问 |
| “这次换工作希望改善哪些方面？” | 多选 | 工时、收入、成长空间可以并存，不能把多项诉求压成唯一目的 |
| “你已尝试过哪些学习方法？” | 多选 | 上课、自学、做项目可以同时发生 |
| “针对这次考试，你目前处于哪个备考阶段？” | 单选，前提是选项互斥 | 限定同一考试与当前阶段，不能混入是否在职等另一维度 |

“当前身份”并不天然是单选：在职与在读可能并存。“主要用途”也不天然代表只允许一种用途。若两项能够同时成立，改成多选，或仅在推荐确实需要唯一取舍时重写题干。不要为了保留单选而替用户制造取舍，也不要用多选把几个独立背景问题塞进同一轮。

选项应简短、同一粒度、避免同义重复。探山每题提供 0 至 5 项建议，保留自由补充入口，不要求选项穷尽所有情况。多选题不要混入“以上都不是”“没有任何需求”“不确定”等与具体选项冲突或语义模糊的选项；用户可以直接用文字表达。也不要提供与逐项选择重复的“以上全部”。“其他”通常由自由输入承接。以后若产品明确需要互斥特殊项，须同时定义并实现前后端互斥规则，不能仅靠提示词假设用户不会一起选。

#### 探山中的一致性约定

- 追问规划结果显式输出 `selection_mode: "single" | "multiple"`，卡片保存并向前端传递该模式。旧卡片或缺失模式默认单选，不从旧题文字猜测升级为多选；非法模式拒绝解析。
- 有选项时在界面显示“单选”或“可多选”，行为与模式一致。多选默认可选全部建议项；不要沿用其他字段的数量限制。已有“关注重点最多两项”等独立字段约束仍按其自身规则执行。
- 服务端依据保存的当前卡片校验，不能信任客户端自行声明模式。单选最多接受一项，多选逐项检查是否属于当前卡片；拒绝重复项、未知项和显式空答案数组。旧的单个字符串答案继续兼容。
- 没有选择时可省略答案，通过自由文字补充；既无有效选择也无文字时不能“继续”，但允许明确跳过。下一轮或切换问题时清空临时选择，提交失败保留输入以便修正。
- 保存问题与全部选中项及补充文字，供后续规划、检索和生成使用。多选不等于给每项相同权重或要求每篇帖子满足所有用途；不要从点击顺序推断偏好排序。硬限制与可兼容需求仍需按用户原意区分。

#### 验证选择模式

至少核对：互斥预算区间只能选一项；可并存用途能选多项并分别取消；单选选择第二项会替换第一项；题干及模式提示一致；单选多项提交在后端被拒绝；多选答案连同文字完整进入下一轮和保存记录；旧卡片默认单选且旧字符串请求仍有效；未知项、重复项和空答案被正确处理；无选择但有文字、跳过、切换题目及失败重试仍可用。

用“同一话题、不同提问意图”检验规划，例如相机总预算应为单选、相机用途应为多选。结构校验和使用预设卡片的测试只能证明模式传递与校验正确，不能证明模型会正确理解每个问题；真实生成结果需另检查题干、选项关系和模式是否匹配。

## 检索与筛选

优先使用知乎搜索寻找原始问题、回答和文章。把主题和最关键的已确认状态转成自然查询，而不是拼接整段聊天或模型追问。初始查询按用途互补：优先找直接解决当前卡点、解释现象或比较方案的内容；关键处境确实影响适用性时，再找相似起点、阶段或限制下的经验。不是固定配额，事实题可能只需一条，比较题也可以分别检索两条路径。

例如用户担心“跨考计算机后仍因非科班被筛”，查询应覆盖跨专业硕士求职筛选与工作后转行求职复盘，不能只搜在职备考方法。每条查询的用途应对应已确认需求；无需新增接口字段。未写进检索词的硬限制仍须在筛选时检查。

主动追问的细节应有预期用途，并检查实际是否用于查询、候选筛选、排序或适用性说明。完全未发挥作用时记为潜在无效追问，不为证明追问有用而强行改变结果；用户主动提供的额外信息不必全部使用。不要收集完背景后仍只搜索宽泛主题，也不要把所有细节硬塞进每条查询导致没有结果。对“已试过但无效”的方法，降低只重复该方法且没有新信息的帖子优先级；解释该方法为何失效、如何调整的内容仍可能有价值。对帖子未交代的关键背景保留不确定性。

探山流程最多两条初始查询，直接相关内容不足时补搜一次，总计最多三次。补搜应针对具体缺口，例如缺少求职结果、关键边界或另一可行路径，不只是同义重复，也不强制搜索反对观点。空结果可放宽非关键表述；不能悄悄移除硬限制，把不适用内容包装成精确匹配。推荐结果只收录知乎帖子；不以站外资料或直答生成文本替代帖子。不足就说明不足，不凑数。

在主题相关的候选中，按证据判断：

1. 是否能帮助当前诉求，是否适用于用户所处阶段与关键处境。
2. 准备推荐的内容及行动前提是否与用户明确的硬限制冲突。核心路径明确冲突的内容不作为可执行的匹配建议；决定可行性的前提未知时不能标为明确适用。区分硬限制与软偏好，不把“更倾向”改成“只能”，也不机械检查与当前内容无关的限制。
3. 内容是否提供具体经历、可用信息和必要上下文；对时效敏感的建议检查已知时间，不能把最近更新等同于内容仍有效。
4. 在适用性与证据质量相近时，再参考接口真实返回的互动量和时间。保留有参考价值的不同经验，避免只推荐支持用户原有倾向的内容。

例如用户只能在职备考，作者曾辞职不代表整篇都无用：依赖全职投入的路线不适用，不依赖辞职的复习方法可按证据标明局部参考。讨论毕业求职筛选的内容，也不一定需要作者具有相同备考时间。判断的是当前推荐内容的前提，不能仅凭作者经历相似或不同决定取舍。

相似身份不是唯一标准：背景不同但能直接解决当前问题的帖子也可能有价值。不得虚构匹配分数、作者经历或帖子适用人群。只看到摘要时，按摘要能够支持的范围判断，不能声称已经读完全文。

## 展示与后续调整

先展示匹配帖子，保留标题、作者（返回时）、忠实摘要和原始链接。对每篇推荐给出简短、可核对的适用理由：用户哪条已知状态与帖子哪项实际内容相符。关键差异或证据不足会影响使用时，一并说明；不能仅写“很适合你”。随后可提供简短辅助总结，区分个人经历与普遍结论。

例如，只有来源确实提到工作后跨专业考研时，才能写“这篇讨论工作后跨专业考研，与你目前工作后想转行的情况接近”；专业方向不同则说明差异。来源未提供作者背景时，不补写“作者与你经历相同”。

用户补充或修改状态后，据此调整查询和排序，不重新收集全部信息；不把旧条件下的结果继续标记为当前匹配。

## 验证效果

验证追问顺序时，覆盖器材选购、技能学习、职业选择和问题解决等不同话题：原问题宽泛且起点最影响适用性时了解起点；有具体卡点时优先深入卡点；原话已说明相关经历时跳过；相同话题下的初次实践与已有经验应进入不同的后续分支；经验无关的事实题不问水平。检查标题提到新手但用户身份未知、跨领域已有经验、拒绝补充等情况，避免贴标签和机械重复。

用同题不同状态的案例检查推荐是否产生有依据的变化，例如在校考研、工作后转行考研和二战后的选择；同时覆盖条件充分直接检索、拒答、纠正条件、只有摘要及没有匹配结果的情况。检查不必要追问、语义重复、硬限制冲突、排序适用性与匹配理由是否有来源支持。比较方案时保持相近搜索预算；不要以追问更多、帖子更多或热度更高代替推荐质量。

增加“粗标签相同、具体处境不同”的对照：同为工作三年转计算机，一人零基础且只能在职备考，另一人已有编程经验且能全职准备，检索或排序应体现差别。同时检查：粗略回答后是否过早结束；充分回答后是否仍机械追问；深入子问题是否与已回答内容重复；每项新增背景是否实际用于匹配；拒答后是否停止索取且未将未知条件当作已满足。手工审阅这些案例只能验证规则一致性，不能代替真实模型和帖子结果的行为评测。

增加“相同背景、不同卡点”的对照：同为零基础学编程，需求不会拆、语句不会写、报错不会排查，应进入不同追问或检索方向。检查连续两轮是否承接上一轮新增信息，是否把已陈述的结果重问一遍，是否用泛泛的“为什么”把诊断负担交给用户。信息充分、用户不知道、拒答和公共知识题仍应按停止规则检索。评估问题是否改变解决方向，不用背景问题数量少或追问听起来抽象深刻代替效果。

对照评测采用相同搜索预算、工具能力、结果数量口径和尽可能固定的候选内容快照，比较“不追问直接检索”与“允许必要追问”。按同一有效需求盲评能否解决卡点、关键诉求覆盖、证据是否支持理由及硬限制冲突，同时记录追问轮数和语义重复。缺少合格结果须单独记录，不能只比较已返回内容的平均质量，也不能为凑数量补入无用帖子。

增加两类停止与匹配案例：同一组帖子可覆盖个人效率和团队效率时不必追问；同一篇文章分别覆盖入门与进阶时允许推荐不变，但理由必须指向对应内容。另检查“作者辞职但方法不依赖辞职”可以局部参考，“作者背景相似但核心方法要求全职”不能作为在职用户的可执行建议。帖子更换率只作诊断，不当作追问收益。以上是评测要求，规则审阅与结构校验不代表已完成真实模型或真实检索效果评测。
