# 按用户当前状态匹配知乎帖子

用于个性化帖子推荐，以及问山的追问、检索和排序设计。成功标准是推荐内容对用户目前处境有参考价值。主题相关或高赞本身不足以证明适用性；不能承诺找到了知乎全站最符合用户的内容。

## 理解当前状态

从原问题和历轮回答中提取与本次需求有关的信息：当前阶段（了解、准备行动、已经遇到问题）、具体处境（相关经历、基础、环境）、现实限制（预算、时间、地点、不可接受的代价）、当前诉求（想解决什么、主要纠结什么）。这些是理解维度，不是必填字段或固定提问顺序。

只把用户明确表达的信息记为已确认；未知信息保持未知。用户最新明确修正优先，保留问答对应关系以理解简短回答。不从一句话、收藏或阅读行为推断身份、收入、心理状态或长期画像；不为推荐默认读取账号数据。

粗标签不等于了解处境。“工作三年”不说明当前职业基础，“想转行”不说明目标，“预算不多”不说明可投入范围。对会改变帖子适用性的维度，继续了解具体起点、期望变化、已尝试的方法与结果、当前卡点和可投入资源。具体到能区分推荐方向即可，不要求精确数字或完整个人履历。

在内部区分“已明确”“仍粗略”“未知”“不愿提供”：已明确的信息不重复问；仍粗略的信息只有在不同解释会改变推荐时才深入；未知信息不默认补全；不愿提供的信息不再索取。只问与当前决策有关的背景，优先用工作年限、技能基础、预算范围等适用性信息，不索要姓名、联系方式、精确住址或具体单位等身份标识。

## 是否追问

每轮先判断：缺失的条件是否可能让不适合用户目前处境的帖子排到前面？在内部明确缺口，以及不同回答会怎样改变检索对象或帖子优先级。若只能解释它怎样丰富 AI 总结，不能解释它怎样改变帖子匹配，就直接检索。

- 每轮追问最影响匹配的一个具体缺口，承接用户刚说的内容，简短说明它会影响寻找哪类经验；可给少量选项，也允许自由补充。不要把多个独立背景问题塞进一轮。
- 已明确回答或拒绝提供的信息不再问，包括换一种表述询问同一缺口。允许在粗略回答上深入到新的具体子问题，例如已知“想转行”后问目标方向；这不等于重复问是否转行。若用户修正造成影响匹配的实质矛盾，做针对性确认。
- 在结束前检查：根据已知信息，是否仍存在两种合理处境，需要明显不同、甚至相互不适用的帖子？若是且用户愿意继续，就追问最能区分两者的缺口；不能只因已知道职业、目的或一个偏好就提前结束。若关键推荐方向已经稳定则立即检索；不为填满画像继续问，总共最多 5 轮，不设最低轮数。
- 客观事实题、明确要求整体了解、直接回答或跳过时直接检索。用户表示不知道或不愿补充时按已知条件继续，并说明适用性尚不确定的部分。
- 当已有结果或轻量检索结果可用时，可依据其中不同的适用场景定位缺口；不把先检索设为每次追问的必要步骤，也不突破调用预算。

例如“要不要考研”尚不明确当前阶段时，可以问“你目前是在校准备考研，还是已经工作后考虑再读研？”；若用户已说“工作三年，想通过考研转行”，不再问是否工作，只有转向领域等缺口会明显改变适用帖子时才继续问。

### 从粗略背景深入到可用条件

以下是可选分支，不是每个话题必须问完的问卷。每轮只选择当前最关键的一项，原话已包含的直接使用。

| 已知信息 | 仍可能影响匹配的缺口 | 可用追问及用途 |
|---|---|---|
| 工作三年，想通过考研转行 | 希望进入的领域 | “你希望通过考研转向哪个领域？还没确定也可以说。”用来区分专业转换与职业探索经验 |
| 希望转向计算机 | 当前专业或编程基础 | “你目前的编程基础大概怎样？”区分零基础跨考与已有技术基础的经历 |
| 零基础，在职备考 | 可持续投入的时间 | “备考期间你每周大约能稳定投入多少时间？”区分在职有限时间与全职备考经验；不自动假设能辞职 |
| 想跳槽，主要因为太累 | 疲惫的具体来源 | “目前最让你累的是工时、工作内容，还是团队相处？”区分换公司、换岗位与沟通应对经验 |
| 已尝试与室友沟通，仍受影响 | 沟通后的反应或实际卡点 | “上次沟通后，对方是什么反应？”区分未达成约定与约定反复失效的经验，不再推荐泛泛的首次沟通帖子 |

若用户已经说“工作三年，文科背景，零编程基础，想跨考计算机，只能在职备考，每周约十小时，想看相似起点的真实经历”，可以开始检索，不再收集年龄、单位或收入来凑画像。目标尚不确定时，优先找相似起点的方向探索经历，不强迫用户先做出决定。

## 检索与筛选

优先使用知乎搜索寻找原始问题、回答和文章。把主题和最关键的已确认状态转成自然查询，而不是拼接整段聊天或模型追问。用互补查询兼顾相似处境的亲历经验与当前决策需要的信息。

追问得到的细节必须产生实际用途：影响某条查询、候选筛选、排序或适用性说明。不要收集完背景后仍只搜索宽泛主题，也不要把所有细节硬塞进每条查询导致没有结果。对“已试过但无效”的方法，降低只重复该方法且没有新信息的帖子优先级；对帖子未交代的关键背景保留不确定性。

问山流程最多两条初始查询，直接相关内容不足时补搜一次，总计最多三次。空结果可放宽非关键表述；不能悄悄移除硬限制，把不适用内容包装成精确匹配。推荐结果只收录知乎帖子；不以站外资料或直答生成文本替代帖子。不足就说明不足，不凑数。

在主题相关的候选中，按证据判断：

1. 是否能帮助当前诉求，是否适用于用户所处阶段与关键处境。
2. 是否与用户明确的硬限制冲突。明确冲突的内容不作为匹配推荐；缺少信息不能当作已满足限制。
3. 内容是否提供具体经历、可用信息和必要上下文；对时效敏感的建议检查已知时间，不能把最近更新等同于内容仍有效。
4. 在适用性与证据质量相近时，再参考接口真实返回的互动量和时间。保留有参考价值的不同经验，避免只推荐支持用户原有倾向的内容。

相似身份不是唯一标准：背景不同但能直接解决当前问题的帖子也可能有价值。不得虚构匹配分数、作者经历或帖子适用人群。只看到摘要时，按摘要能够支持的范围判断，不能声称已经读完全文。

## 展示与后续调整

先展示匹配帖子，保留标题、作者（返回时）、忠实摘要和原始链接。对每篇推荐给出简短、可核对的适用理由：用户哪条已知状态与帖子哪项实际内容相符。关键差异或证据不足会影响使用时，一并说明；不能仅写“很适合你”。随后可提供简短辅助总结，区分个人经历与普遍结论。

例如，只有来源确实提到工作后跨专业考研时，才能写“这篇讨论工作后跨专业考研，与你目前工作后想转行的情况接近”；专业方向不同则说明差异。来源未提供作者背景时，不补写“作者与你经历相同”。

用户补充或修改状态后，据此调整查询和排序，不重新收集全部信息；不把旧条件下的结果继续标记为当前匹配。

## 验证效果

用同题不同状态的案例检查推荐是否产生有依据的变化，例如在校考研、工作后转行考研和二战后的选择；同时覆盖条件充分直接检索、拒答、纠正条件、只有摘要及没有匹配结果的情况。检查不必要追问、语义重复、硬限制冲突、排序适用性与匹配理由是否有来源支持。比较方案时保持相近搜索预算；不要以追问更多、帖子更多或热度更高代替推荐质量。

增加“粗标签相同、具体处境不同”的对照：同为工作三年转计算机，一人零基础且只能在职备考，另一人已有编程经验且能全职准备，检索或排序应体现差别。同时检查：粗略回答后是否过早结束；充分回答后是否仍机械追问；深入子问题是否与已回答内容重复；每项新增背景是否实际用于匹配；拒答后是否停止索取且未将未知条件当作已满足。手工审阅这些案例只能验证规则一致性，不能代替真实模型和帖子结果的行为评测。
